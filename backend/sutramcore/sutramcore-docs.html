SQLite ORM for Node.js

sutramcore

Metadata-driven SQLite ORM built on better-sqlite3. Define your schema once — get automatic joins, type coercion, and clean CRUD.

$ npm install sutramcore better-sqlite3
Synchronous
Instance-based
No global state
Schema-driven joins
01

Installation

better-sqlite3 is a peer dependency — you install it separately to avoid native binary version conflicts.

terminal bash 
# install both
npm install sutramcore better-sqlite3

# generate starter files in database/
npx sutramcore init

The init command creates database/schema.js, database/migrations.js, and database/views.js with examples to get you started.

02

Connection

Create one Sutram instance per database. Each instance is fully isolated — its own connection, schema, and prepared statement cache.

Option A — Pass your own db instance

Use when you already have a db file with your own migration runner. Hand the ready db to sutramcore.

database/db.js js 
const { Sutram }  = require('sutramcore');
const Database     = require('better-sqlite3');
const schema       = require('./schema');

const db   = new Database('./app.db');
// ... your own migration runner here ...

const app  = new Sutram({ db, schema });

module.exports = { app };

Option B — Let sutramcore manage the db

For fresh projects. sutramcore opens the file, runs migrations, sets up views, and returns a ready instance.

database/db.js js 
const { Sutram }  = require('sutramcore');
const schema       = require('./schema');
const migrations   = require('./migrations');
const views        = require('./views');

const app = new Sutram({
  dbPath: './app.db',
  schema,
  migrations,
  views,
});

module.exports = { app };

Multiple databases

two isolated connections js 
const shopDB  = new Sutram({ db: shopConn,  schema });
const auditDB = new Sutram({ db: auditConn, schema });

// completely isolated — different connections, different caches
const product = shopDB.table('product');
const log     = auditDB.table('log');
03

Defining Schema

The schema describes your tables — columns, types, defaults, and relationships. Write it once; sutramcore generates all SQL from it.

Column types

BuilderSQLite typeJS → DBDB → JS
col.id()INTEGER PK AUTOINCREMENT—number
col.number()INTEGER / DECIMALNumber(val)number | null
col.string()VARCHAR / TEXTString(val).trim()string | null
col.boolean()TINYINT 0/1true → 1, false → 01 → true, 0 → false
col.json()TEXT (JSON string)JSON.stringify()JSON.parse()

A complete schema example

database/schema.js js 
const { defineTable, col } = require('sutramcore');

module.exports = {

  // ── simple lookup table ────────────────────────────
  ...defineTable('category', {
    _id:          col.id(),
    name:         col.string().required(),
    active:       col.boolean().default(1),
  }),

  // ── table with hasOne join ─────────────────────────
  ...defineTable('product', {
    _id:          col.id(),
    name:         col.string().required(),
    price:        col.number().default(0),
    category_id:  col.ref('category._id', {   // hasOne
                    as:     'category',
                    select: ['name'],
                  }),
    in_stock:     col.boolean().default(1),
    meta:         col.json(),
    active:       col.boolean().default(1),
  }, {
    // hasMany — orders that include this product
    order_items: {
      hasMany: true,
      table:   'order_item',
      on:      'product_id',   // FK on order_item
      target:  '_id',
      as:      'order_items',
      select:  ['_id', 'qty', 'price'],
    },
    // manyToMany — tags via junction table
    tags: {
      manyToMany: true,
      table:      'tag',
      junction:   'product_tag',
      on:         'product_id',
      target:     'tag_id',
      as:         'tags',
      select:     ['_id', 'label'],
    },
  }),

};
ℹ Raw object style also works: { type: 'string', ref: 'category._id', as: 'category', select: ['name'] }. Both styles are equivalent — use whichever you prefer.
04

Insert

insert examples js 
const { app } = require('./database/db');
const product  = app.table('product');

// insert — returns full object with joins (default)
const newProduct = product.insert({
  name:        'Wireless Keyboard',
  price:       1299,
  category_id: 2,
  in_stock:    true,
});
// newProduct._id = 1
// newProduct.category = { name: 'Electronics' }   ← joined automatically
// newProduct.in_stock = true                      ← coerced from 1

// insert — return only the new _id (faster, use inside transactions)
const id = product.insert({ name: 'USB Hub', price: 499 }, false);
✓ Use full: false inside transactions and loops — it skips the follow-up SELECT and is significantly faster for bulk operations.
05

Update

update examples js 
const product = app.table('product');

// updateById — most common pattern
const updated = product.updateById({ price: 999, in_stock: false }, 1);
// returns full updated row

// update with object WHERE
product.update({ in_stock: false }, { category_id: 3 });

// update with raw string WHERE
product.update({ active: 0 }, "price = 0 AND in_stock = 0");

// full: false — skip return fetch (just returns the id)
product.updateById({ price: 1499 }, 1, false);
ℹ Only fields present in the data object are updated. Missing fields are untouched. Sutramcore runs sanitize in "update" mode.
06

Delete

delete examples js 
const product = app.table('product');

// deleteById — returns number of rows deleted
const count = product.deleteById(5);   // 1

// delete with object WHERE
product.delete({ active: 0 });         // delete all inactive

// delete with raw string WHERE
product.delete("price = 0 AND in_stock = 0");
⚠ delete() requires a WHERE clause — it throws if where is empty to prevent accidental full-table deletes.
07

Get One Row

getById / getOne js 
const product = app.table('product');

// getById — always returns full object with joins
const row = product.getById(1);
// row.category = { name: 'Electronics' }   ← hasOne joined
// row.tags     = [ { _id: 1, label: 'new' } ]   ← manyToMany joined
// returns null if not found

// getOne with object WHERE
const row = product.getOne({ name: 'USB Hub' });

// getOne with raw string WHERE
const row = product.getOne("price < 500 AND in_stock = 1");

// full: false — no joins, plain SELECT * (faster for checks)
const row = product.getOne({ _id: 1 }, { full: false });
// row.category_id = 2   (raw FK, no join)

Get All Rows

getAll examples js 
const product = app.table('product');

// get all active products
const rows = product.getAll({ active: 1 });

// with options — ordering, pagination
const rows = product.getAll({ active: 1 }, {
  orderBy: 'price ASC',
  limit:   20,
  offset:  0,
});

// raw string WHERE for complex conditions
const rows = product.getAll("price BETWEEN 100 AND 500 AND in_stock = 1");

// full: false — no joins, much faster for internal processing
const rows = product.getAll({ active: 1 }, { full: false });

// paginated list — typical API pattern
const PAGE    = 20;
const pageNo  = 2;
const total   = product.count({ active: 1 });
const items   = product.getAll({ active: 1 }, {
  limit:  PAGE,
  offset: (pageNo - 1) * PAGE,
  orderBy: 'name ASC',
});

WHERE Clause — Two Formats

Every method that filters rows accepts either an object or a raw SQL string.

Object format recommended 
// equality, joined by AND
{ active: 1 }
{ active: 1, category_id: 2 }

// all values are bound params
// safe from SQL injection
{ name: userInput }   // safe ✓
String format raw SQL 
// complex conditions
"price BETWEEN 100 AND 500"
"name LIKE '%keyboard%'"
"in_stock = 1 OR price = 0"

// OR conditions (object only does AND)
"cat_id = 1 OR cat_id = 2"
⚠ Raw string WHERE is not parameterized. Use object format for any user-supplied values to avoid SQL injection.
11

Joins

Declare relationships in the schema once — sutramcore generates the SQL automatically whenever you call getById, getOne, or getAll with the default full: true.

hasOne
FK is on this table. Returns a nested object or null.
Declared on FK column
hasMany
FK is on the child table. Returns an array, always.
Declared in joins{}
manyToMany
Through a junction table. Returns an array, always.
Declared in joins{}

hasOne — FK on this table

schema declaration + result js 
// schema
category_id: col.ref('category._id', {
  as:     'category',       // output key on result
  select: ['name'],         // columns to include
})

// result
product.getById(1)
// {
//   _id: 1, name: 'Keyboard', category_id: 2,
//   category: { name: 'Electronics' }  ← joined
//   category: null                     ← if no match
// }

hasMany — FK on other table

schema declaration + result js 
// schema (in joins{} second arg of defineTable)
order_items: {
  hasMany: true,
  table:   'order_item',
  on:      'product_id',   // FK column on order_item
  target:  '_id',           // column on this table
  as:      'order_items',
  select:  ['_id', 'qty', 'price'],
}

// result
product.getById(1)
// {
//   _id: 1, name: 'Keyboard',
//   order_items: [ { _id: 5, qty: 2, price: 1299 }, ... ]
//   order_items: []   ← if none found
// }

manyToMany — through junction table

schema declaration + result js 
// schema
tags: {
  manyToMany: true,
  table:      'tag',
  junction:   'product_tag',   // junction table
  on:         'product_id',     // FK on junction → this
  target:     'tag_id',         // FK on junction → tag
  as:         'tags',
  select:     ['_id', 'label'],
}

// result
product.getById(1)
// {
//   _id: 1, name: 'Keyboard',
//   tags: [ { _id: 1, label: 'wireless' }, { _id: 3, label: 'new' } ]
// }
12

Nested Joins — One Level Deep

When a hasMany child table also has hasOne refs in its schema, sutramcore includes those automatically — no extra config needed.

order with line items — each item includes its product info js 
// order_item schema has:
// product_id: col.ref('product._id', { as: 'product', select: ['name', 'price'] })

// order schema has hasMany → order_item

const order = app.table('order').getById(1);

// order.items is nested with product info inside:
order.items
// [
//   {
//     _id: 1, qty: 2, price: 1299,
//     product_id: 5,
//     product: { name: 'Wireless Keyboard', price: 1299 }  ← nested hasOne
//   },
//   { _id: 2, qty: 1, product: { name: 'USB Hub', price: 499 } }
// ]
ℹ Nesting works one level deep automatically. For deeper nesting (grandchild tables), use raw SQL via app.prepare().

Transactions

All transaction methods are bound to the Sutram instance. Automatic transactions commit on success and roll back on any thrown error.

Automatic — recommended

atomic insert — order + line items js 
const order     = app.table('order');
const orderItem = app.table('order_item');

const orderId = app.transaction(() => {
  const id = order.insert({
    customer_id: 42,
    status:      'pending',
  }, false);                          // false = return id only

  for (const item of cart) {
    orderItem.insert({
      order_id:   id,
      product_id: item.product_id,
      qty:        item.qty,
      price:      item.price,
    }, false);
  }

  return id;    // returned from transaction()
});
// if any insert throws → everything rolls back

Manual — for router-level control

manual begin / commit / rollback js 
app.begin();
try {
  order.insert(data, false);
  orderItem.insert(item, false);
  app.commit();
} catch (e) {
  app.rollback();
  throw e;
}
⚠ better-sqlite3 transactions are synchronous and cannot be nested. Do not call app.transaction() inside another app.transaction().

Raw SQL Access

For complex aggregations, CTEs, or anything BaseTable doesn't handle — use app.prepare() to access better-sqlite3 directly.

raw SQL examples js 
// aggregate query
const stats = app.prepare(`
  SELECT category_id,
         COUNT(*) as total,
         AVG(price) as avg_price
  FROM product
  WHERE active = 1
  GROUP BY category_id
`).all();

// single value
const row = app.prepare(
  `SELECT MAX(price) as highest FROM product`
).get();
const highest = row?.highest ?? 0;

// with bound params
const rows = app.prepare(
  `SELECT * FROM product WHERE category_id = ? AND price < ?`
).all(categoryId, maxPrice);

Migrations

Migrations are an array of arrays. Each inner array is one version. Versions run in order, each in its own transaction.

database/migrations.js js 
module.exports = [

  // version 1 — create tables
  [
    `create table category(
      _id    integer primary key AUTOINCREMENT,
      name   varchar(100) not null unique,
      active tinyint default 1
    )`,
    `create table product(
      _id         integer primary key AUTOINCREMENT,
      name        varchar(200) not null,
      price       decimal(10,2) default 0,
      category_id integer references category(_id),
      in_stock    tinyint default 1,
      active      tinyint default 1
    )`,
  ],

  // version 2 — add column
  [
    `alter table product add column sku varchar(50)`,
  ],

  // version 3 — drop + recreate trigger in SAME version
  [
    `DROP TRIGGER IF EXISTS "old_trigger"`,
    `CREATE TRIGGER "stock_check" AFTER UPDATE ON product ...`,
  ],

];
ℹ Never edit past versions — always add a new array at the end. Each version is atomic: failure rolls back only that version, not the whole history.
