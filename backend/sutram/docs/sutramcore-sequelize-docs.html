sutramcore-sequelize

Sequelize adapter for the sutramCore ecosystem. PostgreSQL, MySQL, MariaDB, MSSQL, SQLite — same API everywhere. AutoDiscover, scaffold, upsert, bulkInsert — all built in.

01

What is sutramcore-sequelize?

sutramcore-sequelize brings Sequelize's multi-dialect support into the sutramCore ecosystem. Same table() / procedure() pattern as sutramcore-mysql — but works with PostgreSQL, MySQL, MariaDB, MSSQL, and SQLite.

Two extra features not in sutramcore-mysql: autoDiscover (connect to any DB and immediately read all tables — no schema.js needed) and scaffold (write the discovered schema to files for developer control).

◈Use sutramcore-mysql when you only need MySQL/MariaDB — it's lighter. Use sutramcore-sequelize when you need PostgreSQL, MSSQL, multi-dialect, autoDiscover, or scaffold.

Pattern 1 — Existing Sequelize Instance

Pass your existing Sequelize instance. Models already registered on it are cached automatically. You manage the lifecycle.

database/db.jsjs
const { Sequelize }  = require('sequelize');
const { Sutram }     = require('sutramcore-sequelize');
const schema         = require('./schema');

const sequelize = new Sequelize({
  dialect:  'postgres',
  host:     'localhost',
  port:     5432,
  username: 'postgres',
  password: 'secret',
  database: 'myapp',
  logging:  false,
});

const db = new Sutram({ instance: sequelize, schema });
await db.connect();

module.exports = { db, sequelize };
✓Pattern 1 is recommended when you already have Sequelize set up in your project. sutramcore-sequelize wraps it — no migration needed.
05

Pattern 2 — autoDiscover

Pass connection config — no schema.js needed. sutramcore-sequelize reads all tables from DB, builds models and schema automatically. Best for exploring existing databases.

autoDiscover — no schema.js neededjs
const { Sutram } = require('sutramcore-sequelize');

const db = new Sutram({
  dialect:  'postgres',
  host:     'localhost',
  username: 'postgres',
  password: 'secret',
  database: 'myapp',
  // autoDiscover: true  ← default, no need to pass
});

await db.connect();
// All tables discovered — ready to use

const rows = await db.table('product').getAll({ active: 1 });

// Write discovered schema to files for developer control
await db.scaffold('./database');
// → database/schema.js
// → database/models/product.js ...
// → database/db.js
ℹsys_, xls_, sqlite_, and SequelizeMeta tables are skipped automatically during discovery.

insert

insert examplesjs
const product = db.table('product');

// full: true (default) — returns complete row with joins
const row = await product.insert({
  name:        'Wireless Mouse',
  price:       799,
  category_id: 2,
});

// full: false — returns primary key only (faster)
const id = await product.insert({ name: 'USB Hub' }, false);
07

upsert ★ extra — not in sutramcore-mysql

Insert if not exists, update if exists. Pass a where clause to check before inserting.

upsert examplesjs
// upsert with where check — insert or update
const row = await product.upsert(
  { name: 'Keyboard', price: 999, sku: 'KB-01' },
  { sku: 'KB-01' },   // where — check if exists
);
// → inserts if sku='KB-01' not found
// → updates price if found

// upsert without where — Sequelize native upsert
await product.upsert({ _id: 5, name: 'Updated' });
08

bulkInsert ★ extra — not in sutramcore-mysql

Insert multiple rows in a single DB call. Much faster than looping insert().

bulkInsert examplejs
const ids = await product.bulkInsert([
  { name: 'Item A', price: 100 },
  { name: 'Item B', price: 200 },
  { name: 'Item C', price: 300 },
], false);
// → [1, 2, 3] — array of inserted PKs

// full: true — returns full rows (slower)
const rows = await product.bulkInsert([...], true);
⚠individualHooks: false — Sequelize hooks (beforeCreate etc.) are skipped for performance. Use loop insert() if you need hooks.
09

getById / getOne / getAll

get examplesjs
const product = db.table('product');

// getById
const row = await product.getById(1);

// getOne — object where or Sequelize Op
const row = await product.getOne({ name: 'USB Hub' });
const row = await product.getOne({ price: { [Op.lt]: 500 } });

// getAll
const rows = await product.getAll({ active: 1 });
const rows = await product.getAll({ active: 1 }, {
  orderBy: 'price ASC',
  limit:   20,
  offset:  0,
  full:    false,  // skip joins
});
ℹSequelize Op operators work directly in where — { price: { [Op.between]: [100, 500] } }, { name: { [Op.like]: '%keyboard%' } } etc.

CTE Reports + Stored Procedures

Pass reports array to constructor. CTE reports use Sequelize named replacements (:param_name). Stored procedures are dialect-aware — correct syntax per DB automatically.

database/reports.jsjs
module.exports = [
  {
    report_name: 'monthly_sales',
    report_type: 'cte',
    cte_sql: `
      SELECT date_trunc('month', date) as month,
             COUNT(*) as orders, SUM(amount) as revenue
      FROM orders
      WHERE date >= :from AND date <= :to
      GROUP BY 1 ORDER BY 1 DESC
    `,
    params: [
      { name: 'from', type: 'string', default: '2024-01-01' },
      { name: 'to',   type: 'string', default: '2024-12-31' },
    ],
  },
  {
    report_name:    'generate_report',
    report_type:    'procedure',
    procedure_name: 'generate_report',
    params: [{ name: 'year', type: 'number', default: 2024 }],
  },
];
15

procedure() — same pattern as table()

usagejs
const db = new Sutram({ instance: sequelize, schema,
  reports: require('./reports'),
});
await db.connect();

// CTE report — :named params
const rows = await db.procedure('monthly_sales').run({
  from: '2024-06-01',
  to:   '2024-06-30',
});

// Stored procedure (dialect-aware)
// postgres  → SELECT * FROM generate_report($1)
// mysql     → CALL `generate_report`(?)
// mssql     → EXEC generate_report @p1=?
const rows = await db.procedure('generate_report').run({ year: 2024 });

// inspect
db.procedure('monthly_sales').getParams();
db.procedure('monthly_sales').getMeta();

// cached — same instance
db.procedure('monthly_sales') === db.procedure('monthly_sales')  // true

Joins

Same schema.js format as sutramCore. Joins are passed as Sequelize include automatically when full: true (default).

schema.js — same formatjs
...defineTable('product', {
  _id:         col.id(),
  name:        col.string().required(),
  category_id: col.ref('category._id', {  // belongsTo → category
                   as: 'category', select: ['name'],
               }),
}, {
  reviews: {                              // hasMany
    hasMany: true, table: 'review',
    on: 'product_id', target: '_id',
    as: 'reviews', select: ['_id', 'rating'],
  },
  tags: {                                 // manyToMany
    manyToMany: true, table: 'tag',
    junction: 'product_tag',
    on: 'product_id', target: 'tag_id',
    as: 'tags', select: ['_id', 'label'],
  },
})
✓hasMany uses Sequelize separate: true internally — avoids cartesian product on large datasets.

Transactions

automatic — recommendedjs
const orderId = await db.transaction(async (tx) => {
  const id = await tx.table('order').insert(
    { customer_id: 5, status: 'pending' }, false
  );
  for (const item of cart) {
    await tx.table('order_item').insert({
      order_id: id, ...item
    }, false);
  }
  return id;
});
⚠Inside transaction(fn), always use tx.table() — not db.table(). The tx object is bound to the transaction.

Manual control

manual begin / commit / rollbackjs
await db.begin();
try {
  await db.table('order').insert(data, false);
  await db.commit();
} catch (e) {
  await db.rollback();
  throw e;
}

Raw Query

db.query / db.queryOnejs
// multiple rows
const rows = await db.query(`
  SELECT p.*, COUNT(r.id) as reviews

scaffold()

After Pattern 2 autoDiscover, write the discovered schema to files. Generates three outputs:

FileContents
database/schema.jssutramCore defineTable + col format — review + add joins{}
database/models/*.jsOne Sequelize model file per table
database/db.jsReady-to-use connection file with Sutram instance
usagejs
const db = new Sutram({ dialect: 'postgres', host, username, database });
await db.connect();   // discovers all tables
await db.scaffold('./database');

// Output:
// ✓ schema.js
// ✓ models/ (12 files)
// ✓ db.js
// Next steps:
//   1. Review schema.js — add joins{}
//   2. Edit models/ if needed
//   3. Use: const { db } = require('./database/db')

CLI — import

Connect to DB and generate schema.js only.

terminalbash
# PostgreSQL
npx sutramcore-sequelize import \
  --dialect postgres \
  --host localhost \
  --user postgres \
  --database myapp

# MySQL
npx sutramcore-sequelize import \
  --dialect mysql \
  --host localhost \
  --user root \
  --password secret \
  --database myapp

# SQLite
npx sutramcore-sequelize import \
  --dialect sqlite \
  --storage ./app.db

# Custom output + overwrite
npx sutramcore-sequelize import \
  --dialect postgres --host localhost --database myapp \
  --out ./src/database \
  --force
