01

What is sutramEngine?

sutramCore is a schema-driven ORM where your schema lives in a JS file. sutramEngine takes that further — it can store your schema, triggers, and CTE reports inside the database itself in sys_ tables. Change schema at runtime without redeployment.

But it's also designed to work alongside sutramCore with zero disruption. You can keep your existing sutramCore code untouched and add engine features incrementally.

Feature sutramCore sutramEngine
Schema location schema.js file sys_ tables or schema.js
Runtime schema change No — redeploy needed Yes — rebootstrap()
Trigger support No Yes — Node.js triggers
CTE reports No Yes — named + parameterized
sutramUI compatible No Yes (managed mode)
CRUD API Full BaseTable API Same + trigger-aware wrappers
02

Installation

terminalbash
npm install sutramengine sutramcore better-sqlite3
◈sutramEngine uses sys_meta to track its own migration version — completely separate from SQLite's user_version pragma which sutramCore uses. Zero conflict, always.
03

Three Initialization Patterns

Pick the pattern that fits your situation. All three produce the same engine API — the difference is where the schema comes from and who manages the db.

PATTERN 1
Reuse sutramCore instance
You already have a sewa Sutram instance. Pass it to engine. Same db, same cache, atomic transactions across both.
existing codebase zero migration direct mode
PATTERN 2
Direct schema
Pass schema.js directly. Engine creates its own Sutram. User manages SQLite tables and migrations.
fresh project no sys_ overhead direct mode
PATTERN 3
Managed (sys_ tables)
Schema lives in sys_table, sys_column etc. Change at runtime. Ready for sutramUI + sutramServer.
runtime changes sutramUI ready managed mode
04

Pattern 1 — Reuse Sutram Instance

The cleanest upgrade path. Your existing sutramCore code stays completely unchanged. Engine borrows sewa.db and sewa's cache. sewa.table() and engine.table() return the exact same BaseTable instance.

database/db.jsjs
const { Sutram }       = require('sutramcore');
const { SutramEngine } = require('sutramengine');
const schema           = require('./schema');

// existing sutramCore setup — NOT touched
const sewa = new Sutram({ db: dbmodal.db, schema });

// engine reuses sewa's db and cache
const engine = new SutramEngine({
  sutram:   sewa,
  triggers: require('./triggers'),  // optional
  reports:  require('./reports'),   // optional
}).init();

module.exports = { sewa, engine };
in your services — existing code untouchedjs
const { sewa, engine } = require('./database/db');

// old code — works exactly as before
const hmpBatch = sewa.table('hmp_batch');
hmpBatch.getAll({ dept_id: 1 });

// new feature — engine adds triggers, reports
engine.insert('new_table', data);   // fires triggers
engine.report.run('monthly_sales');

// transactions across both — FULLY ATOMIC
// same db, same connection, same transaction
sewa.transaction(() => {
  hmpBatch.insert(data, false);               // old table
  engine.table('new_table').insert(x, false); // new table
});

// sewa.table() === engine.table() — same instance
sewa.table('hmp_batch') === engine.table('hmp_batch');  // true
✓importAll() / importSchema() are NOT available in Pattern 1 — engine is in direct mode, sys_ tables are not used for schema. Add new tables via sutramCore's schema.js.
05

Pattern 2 — Direct Schema

No existing sutramCore instance. Pass schema, triggers, reports directly. Engine creates its own Sutram instance. You manage SQLite tables and migrations — engine just drives them.

database/db.js — with existing better-sqlite3 instancejs
const { SutramEngine } = require('sutramengine');

const engine = new SutramEngine({
  db:       dbmodal.db,                          // better-sqlite3 instance
  schema:   require('./database/schema'),
  triggers: require('./database/triggers'),
  reports:  require('./database/reports'),
}).init();

module.exports = { engine };
database/db.js — engine opens the filejs 
const engine = new SutramEngine({
  dbPath:   './app.db',                         // engine opens + sets WAL pragmas
  schema:   require('./database/schema'),
  triggers: require('./database/triggers'),
  reports:  require('./database/reports'),
}).init();
ℹIn Pattern 2, triggers and reports load directly from your arrays — sys_trigger and sys_report tables are not involved. Fast, zero overhead.
06

Pattern 3 — Managed Mode

Schema lives in sys_ tables. Use importAll() to seed from your existing files on first run, or define tables programmatically via engine.schema.createTable(). Designed for sutramUI + sutramServer.

database/db.js — with db instancejs
const engine = new SutramEngine({ db: dbmodal.db }).init();

// seed sys_ tables from your existing files (idempotent)
engine.importAll({
  schema:   require('./database/schema'),
  triggers: require('./database/triggers'),
  reports:  require('./database/reports'),
});
database/db.js — with dbPathjs
const engine = new SutramEngine({ dbPath: './app.db' }).init();

// or define tables in code
engine.schema.createTable({
  table_name: 'product',
  columns: [
    { column_name: '_id',    col_type: 'number',  is_pk: true },
    { column_name: 'name',   col_type: 'string',  is_required: true },
    { column_name: 'price',  col_type: 'number',  default_value: 0 },
    { column_name: 'active', col_type: 'boolean', default_value: 1 },
  ],
});
07

db vs dbPath

For Patterns 2 and 3, you can either pass a db instance or a dbPath. The difference is who manages the database lifecycle.

Option Who opens db Who sets pragmas Who manages lifecycle
db Caller (you) Caller (you) Caller — call db.close() yourself
dbPath Engine Engine (WAL, foreign_keys, busy_timeout) Engine manages the file
ℹIf you already have a db.model.js or DbModal running migrations, always use db — pass the ready instance. Use dbPath for fresh projects where engine is the only thing touching the file.
08

How Bootstrap Works

init() always runs sys_ migrations first, then calls rebootstrap(). What rebootstrap does depends on the mode.

1
Run sys_ migrations
Creates sys_meta, sys_table, sys_column, sys_join, sys_trigger, sys_report etc. Version tracked in sys_meta.engine_version — separate from user_version.
2
Detect mode
direct — schema passed via constructor (Pattern 1 or 2). managed — no schema in constructor, read from sys_ (Pattern 3).
3
Build tableMeta
Direct: uses _directSchema as-is. Managed: BootstrapBuilder reads sys_table + sys_column + sys_join and constructs the tableMeta object in memory.
4
Initialize sutramCore
Direct Pattern 1: reuses sewa — no new Sutram created. Direct Pattern 2 + Managed: creates new Sutram({ db, schema: builtMeta }).
5
Load triggers + reports
Direct: loadFromArray() from constructor arrays. Managed: load() reads from sys_trigger and sys_report.
✓
Ready
All runtime queries use in-memory cache. sys_ tables never touched again until next schema change or startup.
✓rebootstrap() is called automatically after every createTable, addColumn, addJoin etc. You never need to call it manually.

importAll

Managed mode only. Seeds sys_ tables from your existing JS files in one call. Idempotent — entries with same name are skipped. Safe to call on every startup.

importAlljs
engine.importAll({
  schema:   require('./database/schema'),    // required
  triggers: require('./database/triggers'),  // optional
  reports:  require('./database/reports'),   // optional
});
// first run  → inserts all
// next runs  → skips existing names silently

createTable

Managed mode. Inserts into sys_table, sys_column, sys_join, executes CREATE TABLE, then rebootstraps automatically.

createTablejs
engine.schema.createTable({
  table_name: 'product',
  label:      'Products',
  columns: [
    { column_name: '_id',         col_type: 'number',  is_pk: true },
    { column_name: 'name',        col_type: 'string',  is_required: true },
    { column_name: 'price',       col_type: 'number',  default_value: 0 },
    { column_name: 'category_id', col_type: 'number',
      ref_table: 'category', ref_col: '_id',
      ref_as: 'category',    ref_select: JSON.stringify(['name']) },
    { column_name: 'active',      col_type: 'boolean', default_value: 1 },
  ],
  joins: [
    { join_type: 'hasMany', join_key: 'reviews',
      child_table: 'review', fk_col: 'product_id', target_col: '_id',
      as_name: 'reviews', select_cols: JSON.stringify(['_id', 'rating']) },
  ],
});
// engine.table('product') works immediately after this

Creating Triggers

Triggers run in Node.js inside the same transaction as the original operation. Managed mode stores in sys_trigger. Direct mode: define in triggers.js array.

trigger.create — managed modejs
engine.trigger.create({
  trigger_name: 'stock_deduct_on_sale',
  source_table: 'sale_item',
  event:        'INSERT',
  condition_type: 'always',
  actions: [
    {
      action_type:  'update_row',
      target_table: 'product',
      condition:    '_id = {new.product_id}',
      field_map:    { last_sold: 'literal:now' },
    },
    {
      action_type:  'insert_row',
      target_table: 'audit_log',
      field_map: {
        event:      'literal:sale',
        ref_id:     'new._id',
        product_id: 'new.product_id',
      },
    },
  ],
});

Condition types

condition_type Fires when Extra fields
always Every time —
when_col_equals Column equals value condition_col, condition_value
raw_sql SQL expression is truthy condition_sql

CTE Reports

Named SQL queries — CTEs, aggregations, complex joins — stored in sys_report (managed) or loaded from array (direct). Execute on demand with named :param bindings.

create + runjs
// create (managed mode)
engine.report.create({
  report_name: 'revenue_by_category',
  cte_sql: `
    SELECT c.name, SUM(p.price * oi.qty) as revenue
    FROM order_item oi
    JOIN product p  ON p._id = oi.product_id
    JOIN category c ON c._id = p.category_id
    WHERE oi.created_at >= :from
    GROUP BY c._id ORDER BY revenue DESC
  `,
  params: [{ name: 'from', type: 'string', default: '2024-01-01' }],
});

// run — all modes
const rows = engine.report.run('revenue_by_category', {
  from: '2024-06-01',
});

// run with defaults
const rows = engine.report.run('monthly_sales');

// list, update, delete
engine.report.getReports();
engine.report.update('monthly_sales', { cte_sql: `...` });
engine.report.delete('old_report');

Trigger-aware CRUD

CRUD — all patternsjs
// trigger-aware — fires triggers in same transaction
engine.insert('product', { name: 'Mouse', price: 499 });

procedure() — same pattern as table()

Access CTE reports and MySQL stored procedures using the same pattern as table(). Returns a cached ProcedureHandle. Works identically in SQLite and MySQL mode.

database/reports.jsjs
module.exports = [
  {
    report_name: 'low_stock',
    report_type: 'cte',
    cte_sql: `SELECT * FROM product WHERE stock < :threshold AND active = 1`,
    params: [{ name: 'threshold', type: 'number', default: 10 }],
  },
  {
    report_name:    'monthly_report',  // MySQL stored procedure
    report_type:    'procedure',
    procedure_name: 'monthly_report',
    params: [{ name: 'year', type: 'number', default: 2024 }],
  },
];
usage — same for SQLite and MySQLjs
// SQLite engine (CTE only)
const engine = new SutramEngine({ db, schema, reports }).init();

const rows = engine.procedure('low_stock').run({ threshold: 5 });
engine.procedure('low_stock').getParams();
engine.procedure('low_stock').getMeta();

// MySQL engine — same call, CTE or CALL sp()
const mysqlDb = await new MySQLSutram({ ...config, schema, reports }).connect();
const engine  = new SutramEngine({ sutram: mysqlDb }).init();

await engine.procedure('low_stock').run({ threshold: 5 });    // CTE
await engine.procedure('monthly_report').run({ year: 2024 }); // CALL monthly_report(2024)

// cached — same instance
engine.procedure('low_stock') === engine.procedure('low_stock')  // true
◈engine.report is internal — always use engine.procedure(). In MySQL mode, engine automatically proxies to MySQLSutram's report manager — no duplication.

display_format — Template Strings

Controls how a joined object renders as a label — in dropdowns, table cells, or anywhere a readable string is needed. Uses {key} placeholders. Nested keys supported with dot notation.

examplesjs
// simple single field
"{name}"                          // → "Sugar"

// hin : eng pattern
"{hin} : {eng}"                   // → "चीनी : Sugar"
"{item_hin} / {item_eng}"         // → "चीनी / Sugar"

// city with state — nested dot notation
"{city_name} ({state.state_name})" // → "Mumbai (Maharashtra)"

// unit with full name
"{unit_short} - {unit_full}"      // → "kg - Kilogram"

// complex nested
"{subitem_hin} ({unit.unit_short})" // → "आटा (kg)"

How frontend resolves it

frontend utility — one function for all formatsjs
function applyFormat(format, row) {
  return format.replace(/\{([^}]+)\}/g, (_, key) => {
    const val = key.split('.').reduce((obj, k) => obj?.[k], row);
    return val ?? '';
  });
}

// usage
applyFormat('{city_name} ({state.state_name})', row);
// → "Mumbai (Maharashtra)"

MySQL Support

MySQL support is available as a separate package — sutramcore-mysql. It uses the same schema.js format as sutramCore, but all methods return Promises. The same col, defineTable syntax works unchanged.

sutramCore stays synchronous and SQLite-only. If you need MySQL, install the adapter — your existing schema.js requires zero changes.

FeaturesutramCore (SQLite)sutramcore-mysql
MethodsSynchronousAsync — returns Promise
await neededOptional (works, safe)Required
schema.jsSame formatSame format — no changes
JoinsSQLite json_objectMySQL JSON_OBJECT + JSON_ARRAYAGG
Transactionsdb.transaction(fn)await db.transaction(async fn)
sutramEnginePattern 1/2/3Pattern 1 — pass MySQLSutram
ℹTip — await on a sync function is always safe in JavaScript. If you write await table.getById(1) with SQLite, it works perfectly. So you can write all your code with await and switch between SQLite and MySQL by just changing the connection.

Connect

Create a MySQLSutram instance and call .connect(). This creates a connection pool and tests the connection.

database/db.jsjs
const { MySQLSutram } = require('sutramcore-mysql');
const schema           = require('./schema');  // same schema.js — no changes

const db = await new MySQLSutram({
  host:     'localhost',
  port:     3306,
  user:     'root',
  password: 'secret',
  database: 'myapp',
  schema,
}).connect();

module.exports = { db };
✓Connection pool is created internally — connectionLimit defaults to 10. Pass connectionLimit: 20 to increase.

CRUD — Async

Same API as sutramCore — just add await. All methods return Promises.

service.jsjs
const { db } = require('./database/db');
const product = db.table('product');

// insert
const newRow = await product.insert({ name: 'Keyboard', price: 1299 });

// getById
const row = await product.getById(1);
// row.category = { name: 'Electronics' }  ← hasOne joined automatically

// getAll with filter + pagination
const rows = await product.getAll({ active: 1 }, {
  orderBy: 'price ASC',
  limit:   20,
  offset:  0,
});

// update
await product.updateById({ price: 999 }, 1);

// delete
await product.deleteById(5);

// count
const total = await product.count({ active: 1 });
ℹJoins work exactly like sutramCore — hasOne, hasMany, manyToMany all supported. MySQL uses JSON_OBJECT and JSON_ARRAYAGG internally instead of SQLite's json_object.
42

Transactions

Transactions use a scoped connection — all operations inside transaction() are on the same MySQL connection, guaranteed atomic.

automatic — recommendedjs
const orderId = await db.transaction(async (tx) => {
  const id = await tx.table('order').insert({ customer_id: 5 }, false);

  for (const item of cart) {
    await tx.table('order_item').insert({
      order_id: id, ...item
    }, false);
  }

  return id;  // commits on success, rolls back on throw
});
⚠Inside transaction(fn), always use tx.table() — not the outer db.table(). The tx object is scoped to the transaction connection.

With sutramEngine

Pass MySQLSutram instance as sutram to sutramEngine — Pattern 1. Engine detects dialect: 'mysql' automatically and all engine methods become async.

database/db.jsjs
const { MySQLSutram } = require('sutramcore-mysql');
const { SutramEngine } = require('sutramengine');
const schema            = require('./schema');

// connect MySQL
const mysqlDb = await new MySQLSutram({
  host: 'localhost', user: 'root',
  password: 'secret', database: 'myapp',
  schema,
}).connect();

// pass to engine — dialect auto-detected
const engine = new SutramEngine({ sutram: mysqlDb }).init();

module.exports = { engine };
usage — await on everythingjs
const { engine } = require('./database/db');

// trigger-aware CRUD — async
const row = await engine.insert('product', data);
const rows = await engine.getAll('product', { active: 1 });

// router — Express handles async automatically
app.use('/api', engine.router());
