01

What is sutramExcel?

sutramExcel adds Excel import capability to sutramEngine. It auto-derives column config from your existing schema — FK columns become dropdown matchers, required columns become validation rules. You only provide what schema can't know.

Security: only register()-ed tables are accessible. Unregistered tables return 403 — sensitive tables like users or permissions can never be imported via Excel.

LayerPackageResponsibility
ORMsutramcoreSchema, BaseTable, CRUD
EnginesutramengineTriggers, reports, router, UI meta
ExcelsutramexcelImport, FK match, dictionary, error report
UIsutramui-excelAngular components (Phase 2)

04

register()

Whitelist a table for Excel import. Pass a BaseTable instance — not a string. If the table doesn't exist in schema, it fails immediately at startup.

register signaturejs
excel.register(
  engine.table('product'),  // BaseTable instance — not string
  {
    headers:        { ... },  // per-column extensions (optional)
    autoSet:        { ... },  // auto-set values on import (optional)
    duplicateOn:    [...],    // duplicate check columns (optional)
    fullDuplicateOn:[...],    // exact duplicate columns (optional)
    canUpdate:      false,   // allow update on duplicate (optional)
    autoIncrement:  [...],    // auto-increment columns (optional)
    jsonColumns:    [...],    // JSON stringify before insert (optional)
    booleanColumns: [...],    // boolean → 0/1 (optional)
    display_name:   '...',   // shown in table list (optional)
  }
);
✓All config is optional. excel.register(engine.table('category')) works with zero config — schema provides everything needed.

Auto-derived from Schema

sutramExcel reads your schema and auto-builds the import config. You get this for free — no manual configuration needed.

schema.jsjs
...defineTable('product', {
  _id:         col.id(),
  name:        col.string()
                  .required(),
  price:       col.number(),
  category_id: col.ref(
    'category._id', {
    as:     'category',
    select: ['name'],
  }),
  active: col.boolean()
              .default(1),
})
auto-derived configjs
// _id → skipped (auto)

// name → string, required
{ col_name: 'name',
  not_null: true,
  type: 'string' }

// category_id → ref auto
{ col_name:  'category_id',
  name:      'category',
  type:      'ref',
  ref_table: 'category',
  ref_field: 'category_id',
  ref_data:  'name' }

// active → boolean
{ col_name: 'active',
  type: 'boolean' }
SchemaAuto-derived
col.id()Skipped — auto by DB
col.string().required()not_null: true
col.boolean()type: 'boolean' → 0/1 conversion
col.json()type: 'json' → JSON.stringify
col.ref('category._id', { as, select })ref_table, ref_field, ref_data auto

Extend Config

Developer only provides what schema cannot know — alternate names, date types, mix type.

extend examplejs
excel.register(engine.table('product'), {
  headers: {

    // add alternate header names (alt_names append — not replace)
    mm_id: {
      alt_names: ['mm_name', 'मि.म.', 'मिनी मधुबन'],
    },

    // override type — date conversion
    purchase_date: {
      type:      'date',     // Excel serial or string → ISO date
      alt_names: ['date', 'तारीख'],
    },

    // unix timestamp
    rc_date: {
      type: 'unix_date',   // → Unix seconds
    },

    // mix type — item + subitem combo
    item_id: {
      type: 'mix',
      alt_names: ['item_name', 'आइटम'],
    },

    // category FK — extra alt names
    category_id: {
      alt_names: ['cat', 'श्रेणी', 'category name'],
    },
  },
});

autoSet

Automatically set column values on every imported row. Two types — literal values and functions that receive the request object.

autoSet examplesjs
excel.register(engine.table('product'), {
  autoSet: {

    // literal — hamesha ye value set hogi
    is_xl:  1,
    active: 1,
    source: 'excel',

    // function — req se value lena hai
    // missing req value → null → schema default used
    dept_id:    (req) => req.deptId,
    created_by: (req) => req.user?._id,
    branch_id:  (req) => req.headers['x-branch-id'],
  },
});
TypeExampleBehavior
Literalis_xl: 1Always sets this exact value
Functiondept_id: (req) => req.deptIdCalled with Express req object
Function — missingreq.deptId is undefined→ null → schema default used by engine

Duplicate Detection

duplicate configjs
excel.register(engine.table('product'), {

  // check these columns for duplicate
  duplicateOn: ['mm_id', 'item_id', 'purchase_date'],

  // exact match check — all these must match for "full duplicate"
  fullDuplicateOn: ['mm_id', 'item_id', 'purchase_date', 'qty'],

  // allow update when duplicate found with changes
  canUpdate: true,
});
ScenarioResult
No match on duplicateOninserted
Match found, fullDuplicateOn all sameduplicate — skipped
Match found, some fields differ, canUpdate: trueupdate
Match found, some fields differ, canUpdate: falseduplicate — skipped

Import Flow

Frontend calls these routes in sequence — one row at a time for import (streaming progress).

step by stepjs
// Step 1 — frontend parses Excel (SheetJS)
// rows = array of objects, keys = Excel headers

// Step 2 — verify: FK resolve
const res = await http.post('/_sutram/excel/verify/product', {
  rows: excelArrObj,
});
// res.rows         → resolved rows (category_id filled)
// res.correctionList → [ { type:'unit', name:'kulo', rowIndexes:[3,7] } ]

// Step 3 — user resolves corrections in UI
// frontend applies corrections locally to rows

// Step 4 — import one row at a time
for (const row of resolvedRows) {
  const result = await http.post('/_sutram/excel/import/product', { row });
  // result.status: 'inserted' | 'updated' | 'duplicate' | 'rejected'
}

// Step 5 — export rejected rows
const blob = await http.post('/_sutram/excel/error-report', {
  table: 'product', rows: rejectedRows,
}, { responseType: 'blob' });
// → .xlsx file download

What is Dictionary?

Dictionary is a correction memory. When a user corrects "kulo" → unit kg during import, they can save it to dictionary. Next import — "kulo" is automatically resolved to kg without asking again.

flowjs
// First import — "kulo" not found in unit table
// correctionList: [ { type: 'unit', name: 'kulo' } ]
// User selects: kg (unit._id = 5)
// User checks "Dictionary" checkbox

// Frontend saves to dictionary:
http.post('/_sutram/excel/dictionary', {
  type:   'unit',
  name:   'kulo',
  ref_id: 5,
});

// Second import — "kulo" auto-resolved to 5
// No correction needed
◈Dictionary uses its own table xls_dictionary with its own version tracking (xls_meta.xls_version) — separate from user_version and sys_meta.engine_version. Zero conflict.

FK Matching

For every FK column, RefMatcher loads ref table data and matches Excel value. Three-step fallback:

matching orderjs
// Excel cell: "Electronics" (category column)

// Step 1 — direct match against category table
// checks: category_hin, category_eng, category_roman, category_code
// (auto-guessed from column names with _hin/_eng/_roman/_code pattern)
// found → category_id = 3 ✓

// Step 2 — xls_dictionary fallback
// "electronics" in dictionary? → ref_id

// Step 3 — not found
// correctionList.push({ type:'category', name:'Electronics', rowIndexes:[2,5,8] })
// all rows with same value grouped — one correction fixes all

matchFields — auto-guess + override

auto vs overridejs
// auto — guessed from column names
// looks for: _hin, _eng, _roman, _code, _short, _full, name, roll_no
// category table → category_hin, category_eng, category_roman

// override — developer specifies exact fields
excel.register(engine.table('product'), {
  headers: {
    unit_id: {
      matchFields: ['unit_short', 'unit_full'],  // explicit
    },
  },
});

Hindi Normalization

All string matching uses Unicode normalization — critical for Hindi/Devanagari strings where same character can have multiple encodings.

_clean() — applied to all comparisonsjs
_clean(str) {
  return (str || '')
    .toString()
    .trim()
    .normalize('NFC')          // Unicode normalization
    .replace(/\u200B/g, '')   // remove zero-width space
    .replace(/\u00A0/g, ' ')  // non-breaking space → space
    .replace(/\s+/g, ' ')     // collapse multiple spaces
    .toLowerCase();              // case insensitive
}
✓"कुलो", " KULO ", "kulo" — all match the same dictionary entry. Applied to both Excel input and database values before comparison.

mix type — item + subitem

Special type for cascading FK — item and subitem are linked. Excel has two columns, matching is dependent.

mix type config + Excel formatjs
// config
excel.register(engine.table('product'), {
  headers: {
    item_id: { type: 'mix', alt_names: ['item_name', 'आइटम'] },
    // subitem column auto-detected as 'subitem'
  },
});

// Excel columns needed:
// | item          | subitem       |
// | चीनी          | सफेद चीनी     |
// | आटा           | (empty)       |

// matching flow:
// 1. match item → item_id = 5
// 2. match subitem within item_id=5 → subitem_id = 12
// 3. if item not found → correctionList (item + subitem together)

Date Conversion

Excel stores dates as serial numbers. sutramExcel auto-converts based on header type.

typeInputOutput
dateExcel serial (45291) or string (15/06/2024)ISO string — 2024-06-15
unix_dateExcel serial or stringUnix timestamp (seconds)
date configjs
headers: {
  purchase_date:      { type: 'date',      alt_names: ['date', 'तारीख'] },
  insurance_exp_date: { type: 'unix_date', alt_names: ['ins exp'] },
}

Supported string formats

auto-detectedjs
// DD/MM/YYYY  15/06/2024  → 2024-06-15
// DD-MM-YYYY  15-06-2024  → 2024-06-15
// DD.MM.YYYY  15.06.2024  → 2024-06-15
// YYYY-MM-DD  2024-06-15  → 2024-06-15 (as-is)
// Excel serial 45291      → 2024-01-15

Version trackerPackageTracks
